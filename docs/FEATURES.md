# easy-oa 功能清单与实现计划

> easy-oa 是一套面向中小团队的轻量 OA（办公自动化）系统，技术栈与 easy-mall 保持一致：
> 后端 Java 25 + Spring Boot 4.1.2 + MyBatis-Plus + MySQL（管理端 Spring Security + JWT），
> 前端 Vue3 + Vben Admin（Element Plus），预留小程序端（uni-app）扩展。
>
> 仓库结构：
> ```
> easy-oa/
> ├── backend/            # Maven 单体多模块（当前：easy-oa-admin，端口 8091，context-path /）
> ├── db/                 # easy_oa.sql 建库脚本 + migrations/ 幂等增量迁移
> ├── docs/               # 设计文档
> └── web-admin/          # 管理后台前端（@easy-oa/web-ele，dev 端口 5778，代理 /oa（rewrite 去前缀）→ 8091）
> ```

### Phase 2：审批流对接 easy-bpm（规划，不自研）

> 决策（2026-11-16 复核确认）：公司已有独立的审批流中台 **easy-bpm**，easy-oa 不自研审批引擎
> （加签/回退/条件分支等能力自研成本 1~6 人月级），通过 **OpenAPI + 应用密钥（AppKey/AppSecret）** 方式接入。
> 落地三要点：① OA 侧单据状态机兜底 + 定时对账，防回调丢失；② 回调以「单据 ID + 流程实例 ID + 状态」幂等；
> ③ 发起时在 OA 本地保存表单快照，不依赖 BPM 的表单存储。

| 模块 | 功能要点 |
| --- | --- |
| 接入层 | easy-oa 侧封装 easy-bpm OpenAPI 客户端（签名、重试、超时），密钥走环境变量/配置中心，不入库不入仓 |
| 模板同步 | 从 easy-bpm 拉取可用审批模板，映射为 OA 内的发起入口 |
| 发起与回调 | OA 表单提交转发 easy-bpm 创建流程实例；流程状态回调（通过/驳回/撤销）回写 OA 业务单据 |
| 待办与记录 | 「待我审批」跳转 easy-bpm 审批页；OA 内保留发起记录与最终状态台账 |
| 通知 | 审批结果站内消息；预留邮件/企业微信通道 |
| 业务衔接 | 请假（考勤扣减）、用车/用章（台账登记）等单据在审批通过后自动落库 |

### Phase 5.5：个人微信扫码登录

> 设计见 `docs/WECHAT_LOGIN.md`（2026-11-17）。绑定必经密码验证，绝无仅凭微信身份建立登录态的路径。

| 模块 | 功能要点 | 状态 |
| --- | --- | --- |
| 身份绑定 | sys_oauth_binding（unionid 主判据 + openid 兜底，唯一索引一号一微信）；个人中心绑定/解绑 | ✅ |
| 扫码登录 | state（Redis TTL 5min GETDEL 防重放）→ code 换身份 → 命中绑定签发 JWT；未绑定返回 NEED_BIND 引导 | ✅ |
| 绑定引导 | 账号密码确认绑定（bindTicket 一次性 10min）并直接登录；防爆破与密码登录共享计数 | ✅ |
| mock 联调 | oa.wechat.mock=true 跳过微信 API 以固定测试身份走全流程；AppID/Secret 申请后切换 | ✅ |
| 真实接入 | 开放平台网站应用 AppID/Secret + 回调域名部署（申请到位后配置环境变量即可） | ⏳ 待凭据 |

## 约定

- 数据库变更一律走 `db/migrations/YYYYMMDD_xxx.sql` 幂等增量脚本，建库脚本 `db/easy_oa.sql` 仅在新环境初始化用。
- 权限码分段：`system:xxx`、`approval:xxx`、`office:xxx`、`attendance:xxx`、`schedule:xxx`、`doc:xxx`，新增后端校验必须同步登记 `PermissionCodes` 与菜单表。
- 后端模块按 easy-mall 风格：`modules/<域>/controller|service|dto|vo` + 顶层 `entity/mapper`。
